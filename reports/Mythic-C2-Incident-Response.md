# Mythic C2 Incident Response Report

## Executive Summary

This report documents an adversary simulation conducted within the Enterprise SOC Analyst Lab using Mythic Command and Control (C2).

The objective was to simulate a real-world endpoint compromise, validate the organization's monitoring capabilities, observe endpoint telemetry, trigger Elastic Defend detections, and investigate the incident using Kibana.

The exercise successfully demonstrated an end-to-end Security Operations Center (SOC) workflow, including attack simulation, detection, alert generation, investigation, and automated incident ticket creation.

# Attack Timeline

1. Mythic C2 server prepared.
2. Payload generated.
3. Payload executed on the Windows endpoint.
4. Endpoint established a callback to Mythic C2.
5. Post-exploitation commands were executed.
6. Elastic Agent collected endpoint telemetry.
7. Elastic Defend detected suspicious activity.
8. Kibana generated a security alert.
9. The alert was forwarded through the Webhook Connector.
10. An incident ticket was automatically created in osTicket.
11. The SOC investigation was completed.

---

# Observed Activity

Following the successful callback, commands executed included:

- `whoami`
- `ipconfig`

These activities generated endpoint telemetry that was collected by Elastic Agent and analyzed by Elastic Security.

---

# Detection

Elastic Defend detected the simulated malicious activity and generated a security alert.

The alert included:

- Host information
- Process details
- Alert severity
- Detection rule
- Timestamp
- Investigation timeline

---

# Investigation

The investigation followed the standard SOC workflow:

- Reviewed the generated alert.
- Identified the affected endpoint.
- Examined process execution.
- Reviewed endpoint telemetry.
- Correlated related events.
- Confirmed the Mythic C2 callback.
- Verified the executed commands.
- Documented findings.

# Indicators of Compromise (IOCs)
