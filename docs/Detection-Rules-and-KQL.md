# Detection Rules and KQL

## Overview

Detection rules are used within Elastic Security to identify suspicious or malicious activity by analyzing endpoint telemetry and log data. Kibana Query Language (KQL) enables analysts to search, filter, and investigate security events efficiently.

In this SOC Analyst Enterprise Lab, detection rules and KQL queries were used to monitor authentication events, endpoint activity, malware detections, and system logs generated during attack simulations.

---

# Objectives

The objectives of this phase were to:

- Create detection rules
- Generate security alerts
- Validate rule functionality
- Perform threat hunting
- Investigate endpoint activity
- Analyze Windows and Linux logs
- Build practical KQL experience

---

# Detection Rules

Detection rules were configured within Elastic Security to identify suspicious activities across monitored endpoints.

Examples include:

- Windows authentication monitoring
- Linux SSH authentication monitoring
- RDP logon monitoring
- Malware detection
- Endpoint behavior monitoring
- Process execution monitoring
- Suspicious command execution
- Elastic Defend alerts

These rules automatically generated alerts when defined conditions were met.

---

# Threat Hunting with KQL

Kibana Query Language (KQL) was used to search, filter, and investigate security events stored in Elasticsearch.

KQL enabled rapid investigation of endpoint activity and validation of detection rules.

---

# Example KQL Queries

## Successful Windows Logons

```kql
event.code:4624
```

Purpose:

Displays successful Windows logon events.

---

## Failed Windows Logons

```kql
event.code:4625
```

Purpose:

Displays failed authentication attempts.

---

## SSH Authentication Events

```kql
system.auth.ssh.event:*
```

Purpose:

Shows SSH authentication activity on Linux systems.

---

## Successful SSH Logins

```kql
system.auth.ssh.event:"Accepted"
```

Purpose:

Displays successful SSH login events.

---

## Failed SSH Logins

```kql
system.auth.ssh.event:"Failed"
```

Purpose:

Displays failed SSH authentication attempts.

---

## RDP Activity

```kql
event.category:authentication AND winlog.event_data.LogonType:10
```

Purpose:

Shows Remote Desktop Protocol (RDP) logon events.

---

## Endpoint Alerts

```kql
event.kind:alert
```

Purpose:

Displays all security alerts generated by Elastic Security.

---

## Elastic Defend Events

```kql
agent.type:"endpoint"
```

Purpose:

Shows endpoint telemetry collected by Elastic Defend.

---

## Process Events

```kql
event.category:process
```

Purpose:

Displays process creation and execution events.

---

## Windows Security Events

```kql
event.provider:"Microsoft-Windows-Security-Auditing"
```

Purpose:

Displays Windows Security Event Logs.

---

# Detection Validation

Detection rules were validated by generating activity within the monitored environment.

Validation included:

- Windows authentication
- Linux SSH access
- RDP connections
- Endpoint activity
- Malware execution
- Mythic C2 payload execution

Successful detections resulted in alerts that were investigated using Kibana.

---

# Alert Investigation Workflow

The investigation process included:

1. Review generated alert.
2. Identify affected endpoint.
3. Examine event details.
4. Review related process activity.
5. Analyze associated logs.
6. Validate detection rule.
7. Determine impact.
8. Document findings.
